# 样例模式 (Sample Mode) 规范与最佳实践

## 核心定位
- 适用于开发初期业务尚未明确, 需快速产出演示效果或验证想法的阶段
- 本质是快速, 轻量的静态数据展示, 仅追求"即改即见", 不涉及真实数据库建模, 也不要求闭环交互操作

## 机制与控制
- 由环境变量 `SAMPLE_MODE` 控制, 有配套的启动入口与任务套件
- 复用正式接口路由与出入参契约, 无需建立平行的 Mock 服务, 接口内部通过判断 `环境变量.SAMPLE_MODE` 走样例分支

## 编写原则
- 正式分支占位：在逻辑未确定时, 可仅编写样例分支, 正式分支推荐直接使用反模式的 `throw new Error('正式接口未实现')` 占位, 既避免定制专用错误码, 也便于排查统计未实现的接口
- 坚持硬编码, 杜绝过度设计：优先使用反模式的硬编码假数据, 不要在内存中构建复杂的数据映射, 状态流转或数据结构抽象, 保证极高的修改灵活性
- 样例数据应作为接口入口中的薄虚拟数据层, 就近写在对应接口的 `SAMPLE_MODE` 分支内; 不为样例建立独立的模型, 仓储, 服务, 工厂, 状态容器或跨接口共享数据文件
- 容忍联动断裂, 无需全量适配：样例模式只对单点展示负责. 如果当前接口编造的假数据影响了下游接口(例如查询接口返回的编造的 ID 导致编辑接口报错), 不要修改下游接口去兼容, 坚持"能用即可, 无需尽善尽美"
- 参考示例：可参考 `src/interface/demo/crud/user/read/index.ts`

## 长期价值
- 即使后续补全了正式业务逻辑, 样例分支仍具有保留价值, 可作为直观, 无歧义的接口返回示例, 便于调用方快速理解数据契约。
