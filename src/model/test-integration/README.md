# 集成测试模型

`集成测试`表示一个有明确名称、能够独立执行验证的测试概念。登录与注册测试等具体测试通过继承表达各自的业务操作，文件默认导出子类。

```ts
class 登录注册集成测试 extends 集成测试 {
  public constructor() {
    super('登录与注册')
  }

  public override async 运行(): Promise<void> {
    // 准备数据并执行断言。
    // 自己创建的资源通过 finally 释放，断言失败直接抛错。
  }
}

export default 登录注册集成测试
```

基类只维护测试名称与执行契约，不依赖数据库、文件扫描或报告机制。名称在构造时必须有效；业务依赖使用顶部静态导入，构造实例不启动业务资源。配置在应用启动或实际获取时严格校验，数据库与任务资源通过全局资源按需创建并复用；仅导入测试声明不读取环境文件或启动业务资源。

脚本执行器扫描 `test/integration/` 的测试文件，校验默认导出为 `集成测试` 的子类并实例化，再按顺序调用 `运行(附加参数们)`。运行没有抛错即通过，抛错则记录失败并继续其他选中实例。

计时、日志收集和报告保存由脚本统一处理。用例不读取命令行全局参数，不自行退出进程，也不返回进程退出码；整个命令结束后由入口统一退出。各实例共享当前进程的模块缓存和应用单例，自己创建的资源仍需显式释放。
