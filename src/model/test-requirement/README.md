# 需求测试领域模型

需求测试以“想证明什么”为中心，不限定浏览器、HTTP 或命令等技术手段。核心领域只保留能够稳定指认的概念：

```text
需求
└── 验收点[]

流程
├── 流程步骤[]
│   ├── 行为
│   └── 观察
├── 覆盖验收点[]
└── 选择结果 ──验证──> 选择条件[]

选择
└── 选择选项[]

行为 / 观察 ──提交──> 流程步骤附件[]
运行器 ──执行流程──> 流程运行描述
```

`流程运行描述`只是一次运行返回的数据，使用普通类型表达。测试目录扫描、后端启停、浏览器创建、附件文件处理和报告渲染由各自的运行入口处理。

## 核心概念

- `需求`描述想要什么，并拥有一组可判定的`验收点`。
- `状态`描述系统所处的状态。状态经过行为迁移后仍然是状态，可以连续组合多个行为。
- `流程`是为了证明验收点而声明的运行过程，由有序流程步骤组成。
- `行为`是状态迁移操作。它接收当前系统内容并返回迁移后的系统内容，可以是浏览器点击、HTTP 请求或命令调用。
- `观察`只读取当前系统状态。满足预期时正常结束，不满足时直接抛错并终止流程。
- `流程步骤附件`是行为和观察都可以提交的文本或图片，按提交顺序归入该步骤的运行记录。
- `选择`描述测试开始前需要确定的业务决策点，`选择结果`保存一次具体决定，`选择条件`判断这组决定是否允许。
- `运行器`负责按顺序执行流程，并返回步骤记录、日志和已证明验收点。

## 选择与条件

```ts
let 账号类型 = new 选择({
  名称: '账号类型',
  说明: '决定创建普通用户还是管理员用户。',
  选项们: [
    { 值: '普通用户', 标签: '普通用户', 说明: '不具备管理权限。' },
    { 值: '管理员用户', 标签: '管理员用户', 说明: '具备管理权限。' },
  ] as const,
})

let 结果 = new 选择结果([账号类型.作出选择('管理员用户')])
let 条件 = new 选择条件('必须选择管理员用户', (当前结果) => 当前结果.读取(账号类型) === '管理员用户')
结果.验证(条件)
```

选择模型只负责有限选项、唯一赋值和条件判定。它不枚举全部合法组合，不构造选择前缀图，也不进行可达性分析。流程可以持有选择结果和选择条件；行为如果需要根据选择改变操作，可以直接读取同一个选择结果。

## 状态迁移

```ts
let 初始状态 = new 状态<系统状态>(系统)

let 已登录 = await 初始状态.迁移(登录行为, 提交附件)
let 已创建用户 = await 已登录.迁移(创建用户行为, 提交附件)
```

`状态`持有系统在当前时刻的实际内容，不保存未来要执行的行为。每次迁移都会返回一个新的状态对象；底层内容可以继续复用同一个浏览器句柄或 HTTP 客户端。多个前置行为应按执行顺序分别列入流程步骤，以便运行记录分别显示每个行为的结果。

## 步骤附件

```ts
let 观察首页 = new 观察<系统状态>('观察首页', async (系统, 提交附件): Promise<void> => {
  if ((await 系统.首页可见()) === false) throw new Error('登录后未显示首页')
  提交附件([{ 类型: '文本', 内容: '登录后首页可见' }])
})
```

行为和观察都可在执行期间调用 `提交附件()`，传入混合文本和图片的数组。图片使用 `{ 类型: '图片', 内容类型: 'image/png', 内容: 截图的Base64 }`，也支持 JPEG 和 WebP。步骤抛错时，已提交的附件仍随失败记录保留。观察通过正常结束或抛错表达验证结果，附件用于记录操作或观察到的内容。

## 执行边界

```ts
let 描述 = await new 运行器(初始状态).运行(登录流程)
```

运行器拥有一条流程的初始状态，并按 `当前状态 = await 当前状态.迁移(行为, 提交附件)` 推进。返回描述包含最终状态。`test/requirement/` 下除 `helper/` 外的 `.ts` 文件默认导出 `需求测试` 子类，由脚本实例化。构造时登记需求、流程与测试服务配置。`准备数据(工具)` 为每次尝试准备业务数据，框架将工具放进流程的初始上下文。

基类按流程名称调用核心运行器。外围脚本筛选流程，为每次尝试创建工具，并在结束时收集附件和释放资源。每步可以收到来自工具的自动证据与用例手动提交的附件。

浏览器、数据库和后端日志都是可选工具。浏览器按名称打开独立会话，可自动或演示运行。数据库工具通过测试库的只读连接执行查询。需要项目后端的流程使用脚本统一启动的测试服务，人工验收流程由外围脚本跳过。自定义 HTTP 或命令操作可以接收 `工具.取消信号`，让正在执行的步骤响应中断。

需求测试不提供流程快照、恢复或中途续跑。每条流程都从测试入口提供的新初始状态开始，以免把调试基础设施混入核心模型。
