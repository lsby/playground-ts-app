# 浏览器测试引擎

`浏览器测试引擎`表示绑定一个 Playwright 页面的浏览器测试会话。登录演示、表单自动验证等各自使用独立实例。它组合页面、运行模式与步骤作用域，将页面操作和演示呈现封装为统一能力。

引擎作为测试技术模型放在 `src/model/browser-test/`。高亮属于引擎的内部操作，卡片渲染属于提示卡片的私有方法。需求、流程、行为、观察和步骤附件由 `src/model/test-requirement/` 定义。

## 对象边界

- 构造时显式传入页面和自动或演示模式，拒绝已经关闭的页面和非法模式。
- 点击、输入、勾选和选择只接受当前页面的 Locator，原生操作参数与返回值继续保留。
- `截图()` 返回当前视口的 PNG。可传入 `{ x, y }` 视口坐标或当前页面的 Locator 加上点击标记。传入 Locator 时，引擎会先滚动到目标并标出其可见区域的中心。标记仅绘制在截图里。
- 演示模式会在元素操作前按需滚动页面和内部滚动容器，再绘制高亮。步骤说明可以传入目标 Locator，让目标在提示卡出现前进入视口。
- 模式只影响说明、高亮和等待，业务操作与断言在两种模式下相同。
- 作用域在引擎实例内管理，并隔离异步执行分支；嵌套设置继承外层，结束后恢复。粒度是调用方的业务描述，框架不根据文字推断行为。
- 同一个引擎同时展示多张提示卡片会报错，避免替换卡片后遗留未完成的等待。
- 页面和浏览器由调用方管理生命周期。引擎使用原生页面，不负责启动被测服务或清理数据库。

## 使用方式

需求测试为每次尝试提供浏览器工具。流程可以通过 `工具.浏览器.打开(名称, 初始地址)` 打开会话，再通过 `获得(名称)` 取到引擎。每个具名会话拥有独立的登录状态，并保存自己的最终截图与 Trace。

```ts
let 打开登录页 = new 行为<需求测试上下文>('打开登录页', async (上下文): Promise<需求测试上下文> => {
  await 上下文.工具.浏览器.打开('管理员', '/demo/login.html')
  return 上下文
})

let 观察登录页 = new 观察<需求测试上下文>('登录页显示账号输入框', async ({ 工具 }): Promise<void> => {
  let 引擎 = 工具.浏览器.获得('管理员')
  await 引擎.验证可见(引擎.按角色('textbox', { name: '用户名' }))
})
```

需求测试运行器为每个步骤开启取证作用域。引擎在导航完成、操作之前和等待达成时采集画面，并在步骤结束或失败时记录现场。同一步骤的不同会话以名称区分。自动标注使用当前视口内的目标，采集画面时不主动滚动页面。

使用 `验证可见(目标)` 或 `验证隐藏(目标)` 时，引擎先执行原有的 Playwright 断言，成功后再采集证据。直接调用 `引擎.断言()` 或原生 Locator 时，步骤结束会再次观察页面，与最近结果图相同的画面只保留一份。截图采集错误独立报告，步骤状态由操作和断言的结果决定。

开场、步骤说明和完成卡片在独立的 `iframe` 文档内接收指针与键盘事件，卡片按钮和拖动操作与被测页面的事件隔离。前置准备可用 `作用域()` 关闭步骤说明与操作动画，离开作用域后恢复外层设置。
